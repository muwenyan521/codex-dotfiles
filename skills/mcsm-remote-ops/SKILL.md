# MCSM 远程运维

## 连接

把会话中已确认的值绑定到以下槽位，不在 skill 中存放密钥：

```bash
ssh -o BatchMode=yes -o ConnectTimeout=10 -p SSH_PORT ACCOUNT@HOST
INSTANCE_DIR='INSTANCE_DIR'
```

首次连接只读取状态，确认 `HOST`、`SSH_PORT`、`ACCOUNT`、`INSTANCE_DIR`、Daemon 容器名和 Minecraft 容器名。不要从旧对话猜测可能漂移的容器状态。

详细命令、已确认陷阱和验收清单见 [references/server-runbook.md](references/server-runbook.md)。

## 强制约束

1. 尽可能减少重启次数与下线时间。把调查、下载、构建、配置生成、静态检查、备份和预上传全部放在服务器在线阶段完成。
2. 默认只安排一个维护窗口和一次 Minecraft 完整重启。发现新问题时先在离线副本修完，不用线上重启逐个试错。
3. 不用 PlugMan 或同类工具热替换依赖复杂的插件。只有插件官方明确支持的配置重载才使用 reload。
4. 不泄露 MCSManager 访问密钥、数据库密码、Cookie 或令牌。过滤 Daemon 启动日志中的密钥行。
5. 不改变玩家余额键、货币 ID、UUID、世界数据或物品数据，除非用户明确要求迁移。
6. 修改前保留原件哈希和完整配置；修改后提供可执行回滚并先运行其只读预检。
7. 重启对玩家只称为“常规维护”，除非用户另有要求。

## 工作流

### 1. 建立在线基线

同时收集：

- `docker ps -a`、容器重启策略、`OOMKilled` 和启动时间。
- `logs/latest.log` 的插件版本、`Done`、异常计数和当前在线玩家。
- 目标 JAR、配置目录、`.paper-remapped` 文件和 SHA1。
- 需要保护的真实数据基线，例如余额、限额、物品或权限。

先形成至少三个可区分的故障或兼容性假设。不要把“插件显示 Enabled”视为集成成功。

### 2. 在线准备全部变更

- 从官方标签、发布页或源码确认版本，不只看文件名。
- 对跨插件调用用 `javap`、API 源码或最小驱动检查 JVM 方法签名。
- 在本机编译并跑构建、JAR 完整性、配置解析和回归测试。
- 生成最终目录树，而不是维护窗口中边改边试。
- 上传到备份目录下的 `incoming/`，校验本地与远端哈希一致。
- 准备 `--check` / `--apply` 回滚脚本；`--apply` 必须拒绝在 Daemon 或 Minecraft 仍运行时执行。

### 3. 单次维护窗口

按顺序执行：

1. 提前通知玩家一次常规维护并给出明确倒计时。
2. 如会停止 Daemon，先暂停自动守护定时器并临时把 Daemon 重启策略设为 `no`。
3. 执行 `save-all flush`，再优雅停止 Minecraft。
4. 确认 Minecraft 容器已停止或因 `AutoRemove=true` 被移除。
5. 把旧 JAR、配置和对应 `.paper-remapped` 文件移动到带时间戳的备份，不直接删除。
6. 原子安装全部预上传文件。
7. 恢复 Daemon 的 `restart=always`，启动 Daemon，让 MCSManager 按既有自动启动策略重建实例。
8. 恢复守护定时器，只等待这一次启动完成。

如果安装前检查失败，在服务器尚未停服时终止维护。安装后启动失败，立即在同一窗口回滚，不开启第二轮试错重启。

### 4. 真实验收

要求同时满足：

- Minecraft 日志出现当前启动的 `Done (...)`。
- Daemon、Web 和 Minecraft 容器状态正确，`OOMKilled=false`。
- 目标插件版本正确，目标异常从当前启动起为 0。
- 依赖插件确实挂接，例如商店、Vault、Jobs 和其他经济消费者。
- 使用真实入口完成一次最小可逆业务测试。
- 数据读回与基线一致；测试增量必须撤回。
- 回滚脚本 `--check` 成功。

经济系统至少执行：读取基线、增加 `0.01`、读回、扣除 `0.01`、再次读回。最终数值必须与基线逐位一致。

### 5. 收尾

- 向玩家宣布常规维护完成。
- 清理本地调试副本、挂起的 `docker attach`、临时日志和未使用构建产物。
- 保留生产备份、补丁、哈希、验证记录和回滚脚本。
- 最终报告重启次数、实际下线时长、版本、数据验证结果、备份路径和未能执行的真实场景。
