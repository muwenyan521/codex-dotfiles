# Verification Before Completion

1. 重读用户请求和适用规则，逐项映射到可观察证据。
2. 运行最窄有效检查，再按风险扩展到测试、构建、集成或 E2E。
3. 前端操作真实页面并检查控制台；服务调用真实端点；CLI/TUI 运行实际入口。
4. 重新检查 diff、文件权限、秘密泄露、后台进程和用户已有改动。
5. 区分本次失败、历史失败和环境阻塞；没有证据的项目标为未验证。
6. 最终报告修改、验证结果、剩余风险、备份和可运行回滚。
